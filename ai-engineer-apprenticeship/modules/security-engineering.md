# Security engineering: границы данных и доступа

[Карта модулей](README.md) · [Курс CS50 Cybersecurity](../WORK_INTEGRATED_ROADMAP.md)

Цель — проверить конкретные границы одного своего сервиса. Практика выполняется на разрешённом dev/staging с синтетическими данными.

## Порядок

[OWASP Top 10](https://owasp.org/projects/top-ten) → [API Security](https://api-security.owasp.org/) → [LLM Top 10](https://genai.owasp.org/llm-top-10/) → [NIST SSDF](https://csrc.nist.gov/Projects/ssdf). Читать категории, соответствующие выбранному потоку; широкий обзор даёт CS50 Cybersecurity.

## Практика

1. Нарисовать browser → API → data store → model/tools → output. Отметить пользователей, документы, tokens и разрешённый egress.
2. Для каждой границы записать, кто принимает решение о доступе и что происходит при отказе.
3. Создать двух учебных пользователей и два набора документов. Проверить прямой запрос чужого ID, поиск, export и retrieval context.
4. Подать учебный документ с инструкцией нарушить задачу. Проверить, что текст документа не даёт новых полномочий tools или egress.
5. Проверить, что секреты не попадают в UI, логи и artifact pipeline. Если сервис получает URL, отдельно проверить допустимые назначения в рамках своего стенда.
6. Составить таблицу: риск → проверка → наблюдение → исправление → повторная проверка.

Недоступная зависимость должна приводить к заранее определённому поведению. Решение модели по prompt не заменяет серверную авторизацию.

## Выход

Одна схема границ, воспроизводимый негативный сценарий и список открытых рисков с ответственным. [Security Review](../exams/MASTER_EXAMS.md#security-review).
